## 先校准方向：你要做的不是「训练模型」

AI Agent 应用开发的本质是**用编排把模型、工具、状态和人机交互组装成一个能完成任务的系统**。核心工作是工程，不是算法：调用模型 API、设计工具契约、管理上下文与记忆、控制循环、处理流式交互、做评估与容错。

这与前端的日常高度同构：

| 前端熟悉的东西 | Agent 里的对应物 |
|---|---|
| 组件 props / 类型约束 | 工具 JSON Schema、结构化输出 |
| 表单校验与错误态 | 工具参数校验、模型输出校验与重试 |
| 全局状态管理 | 会话状态、Agent 状态机、checkpoint |
| SSE / WebSocket 流式渲染 | Token 流、工具调用事件流 |
| 接口联调与降级 | 模型/工具超时、重试、多模型容灾 |
| 性能优化与埋点 | Token 成本、P95 延迟、Tracing、Evals |

**结论**：TypeScript 路线完全够用，不需要先补机器学习数学，也不需要一开始转 Python。

## 五阶段路线（按每周 8–10 小时估算）

| 阶段 | 周期 | 主题 | 核心产出 | 验收标准 |
|---|---|---|---|---|
| 01 建立体感 | 第 1–2 周 | LLM API、消息结构、流式、结构化输出 | 一个 Vue/Nuxt 流式聊天页 | 能解释 Token 与上下文窗口；能手写原生 API 调用；能逐字渲染 |
| 02 让模型能做事 | 第 3–6 周 | Prompt、Function Calling、MCP | 一个会查数据/调业务接口的工具助手 | 工具调用参数可校验、可重试；能防提示注入的基本形态 |
| 03 有知识、有章法 | 第 7–10 周 | RAG、Agent 循环、编排、框架选型 | 私有文档问答 + 多步任务 Agent | 回答带引用；能设置最大步数与停止条件；能追踪每一步 |
| 04 前端主场 + 生产化 | 第 11–14 周 | Agent UI、Evals、Tracing、安全与成本 | 可演示、可观测、可容错的产品级 Demo | 有指标看板；有 20 条以上评测集；工具失败时用户无感降级 |
| 05 作品与求职 | 持续 | 项目打磨、开源、技术输出 | 2–3 个公开仓库 + 量化简历描述 | 项目有 README、架构图、录屏；指标可复现 |

> 时间不是硬指标。判断能不能进入下一阶段的唯一标准是「上一阶段的产出是否真的跑通并被自己挑过毛病」，而不是「视频看完了」。

## 阶段 01：建立体感（第 1–2 周）

**学什么**：Token / 上下文窗口 / system-user-assistant-tool 消息角色 / temperature 等采样参数 / SSE 流式 / JSON Schema 结构化输出 / 基础成本模型。

**做什么**：先**不用框架**，用原生 `fetch` 调一次 OpenAI 兼容接口，打印完整请求与响应；再把接口包成 Nuxt server route，前端用流式渲染出打字机效果。

**验收**：
- 能说出为什么「把整段对话历史每次都发过去」会既贵又容易溢出
- 能区分「模型没按 JSON 返回」与「我的解析写错了」
- API Key 只存在于服务端环境变量

延伸阅读：[LLM 调用基础](/ai-agent/03-llm-fundamentals)、[前端集成](/ai-agent/10-frontend-integration)

## 阶段 02：让模型能做事（第 3–6 周）

**学什么**：System prompt 结构、Few-shot、上下文预算、Function Calling 的 tool loop、Zod 校验、MCP 三原语。

**做什么**：给助手接 2–3 个真实工具（查订单、查天气、写待办），把每次工具调用的参数与结果打到界面上；再用 MCP 把其中一个工具暴露出去，让另一个客户端也能调用。

**验收**：
- 工具描述清晰到「模型不会选错工具」
- 参数校验失败时，把错误信息作为工具结果回喂模型并让它自我修正
- 危险操作（写库、发消息）必须有人类确认

延伸阅读：[提示词与上下文工程](/ai-agent/04-prompt-and-context)、[工具调用](/ai-agent/05-tool-calling)、[MCP](/ai-agent/06-mcp)

## 阶段 03：有知识、有章法（第 7–10 周）

**学什么**：分块与 Embedding、向量检索与重排、引用归因；ReAct / Plan-and-Execute / 状态图；短期与长期记忆；主流框架取舍。

**做什么**：把本站的 Markdown 文档做成知识库问答（答案必须带来源链接）；再做一个「先拆解、再逐步执行、中途可暂停」的多步 Agent。

**验收**：
- 能解释「为什么这次检索没命中」并给出改进手段
- Agent 有最大步数、超时和预算上限，不会无限循环烧钱
- 每一步都有 trace：输入、模型选择、工具、耗时、Token

延伸阅读：[RAG](/ai-agent/07-rag)、[Agent 循环与编排](/ai-agent/08-agent-loop-and-orchestration)、[框架选型](/ai-agent/09-frameworks)

## 阶段 04：前端主场 + 生产化（第 11–14 周）

**学什么**：Agent UI 的事件模型、增量渲染与取消、Human-in-the-loop 交互；Evals 数据集、Tracing、成本/延迟优化、提示注入与权限边界、降级与容灾。

**做什么**：给项目加上「工具调用时间线」「中断/续跑」「审批弹窗」，再补一套 20–30 条评测用例和成本看板。

**验收**：
- 工具超时/模型 5xx 时界面给出可操作提示，而不是白屏或转圈到天荒地老
- 换一个模型供应商，业务代码改动集中在一处
- 能拿出「任务成功率 / P95 延迟 / 单次成本」三个数字

延伸阅读：[前端集成](/ai-agent/10-frontend-integration)、[生产化](/ai-agent/11-production-engineering)

## 阶段 05：作品与求职（持续）

不做「第 N 个聊天框」。挑一个有真实约束的垂直场景（内部知识库、工单处理、报表解读），把可靠性、权限、评估做扎实，写清楚架构取舍与失败复盘。**一个能讲清楚为什么这样设计的项目，胜过五个 Demo。**

项目清单与资源见 [实战项目与推荐资源](/ai-agent/12-projects-and-resources)。

## 五个常见误区

1. **先啃 Transformer 推导**——应用开发阶段用不上，先做出能跑的东西再回头补直觉。
2. **一上来就学框架**——框架帮你封装了 loop，也顺便藏起了最重要的概念。先手写一次原生调用和一次 tool loop。
3. **追新框架追到焦虑**——2026 年主流框架能力已趋同，差异主要在执行模型、持久化、生态。选一个用到底。
4. **只跑通 happy path**——面试官问的永远是「工具挂了怎么办」「上下文超了怎么办」。
5. **不做评估**——「感觉回答变好了」不是工程结论。没有 evals，任何 prompt 改动都是赌博。
